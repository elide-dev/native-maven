Native Maven
============

Native Maven is a subproject of [Elide](http://elide.dev) with the goal
to bring _native speed_ to Java development. Native Maven uses the Elide
expertise to repackage [Apache Maven](README.md) into a native executable
that starts fast, runs fast and optimizes for a selected developer workflow.

## Use via Elide Wrapper

The way to use _Native Maven_ is to [download and install Elide](https://elide.help/docs/installation)
and then execute:
```
$ elide mvn -- package
```
in a directory with an existing Maven project.

Elide binary doesn't include support for the Apache Maven when downloaded - there are other
technologies that help Elide provide the best Kotlin/Java developer
experience. However, given the enormous popularity and stability of Maven,
each `elide` binary knows to download appropriate Maven support.

When asked, reply _yes_, the _Native Maven_ support gets downloaded and can be
used. Next time the downloaded support is used immediatelly and it delivers
**2x speed ups** when running typical `pom.xml` builds.

## The Cost of the Speed Up

Speeding a JVM application like Maven up isn't easy and it comes at some
cost. The cost of _Native Maven_ is slightly restricted flexibility. When
preparing the native executable some Maven plugins have to be _"baked in"_,
those are going to run fast. The others are likely to slow the execution down
a bit.

### Flavors

The set of _"baked in"_ plugins is called a **flavor** of _Native Maven_.
There are flavors for all commonly used technologies and their list is
constantly growing:

- `generic@4.1.0` supports all plugins available in an empty (pluginless) `pom.xml`
  of Maven 4.1.0 - useful for starting from scratch or pure JVM standard edition
  development
- `spring@x.y.z` supports projects generated by [Spring Initializr](https://start.spring.io/)
  including technologies like Hybernate, Kafka, Neo4j and co. The currently supported
  Spring versions are `4.1.0` and `4.0.7`

Use `--flavor` option to request particular flavor to be downloaded and used.
For example:

```bash
$ elide mvn -- --flavor=spring@4.1.0 package
```

Uses a flavor of _Native Maven_ with support for Spring 4.1.0. Such a flavor
may work for other types of Maven projects as well, but its plugins are clearly
optimized for the Spring 4.1.0 technology.

### Mode

Modes tell the _Native Maven_ what shall happen when a particular Maven plugin
is needed, but it is not available among the _"baked in"_ plugins. Mode gets
specified by `--mode` argument. There are following supported values:

- `elide mvn -- --mode=native` - runs all the plugins in _native mode only_ - e.g.
   those plugins must be _"baked in"_ into appropriate _flavor_ of _Native Maven_
   binary. If the plugin isn't _"baked in"_, then an **error is emitted** and
   the execution of the process ends with an error. The error message contains
   suggestions of possible follow up actions. Running fully in _native mode_
   is usually the fastest (to start, as well as to run).

- `elide mvn -- --mode=mixed` - runs all the _"baked in"_ plugins in native mode
   and all the others _one by one_ in a dedicated HotSpot JVM. This mode provides
   the best balance of _native speed_ and compatibility especially with proper
   selection of the most suitable **flavor**. _"Baked in"_ plugins run fast
   (proper flavor guarantees there is many of them) and other plugins are also
   supported.

- `elide mvn -- --mode=legacy` - disables the _Native Maven_ support and executes
   all the plugins in a HotSpot JVM in a single batch. This mode doesn't provide
   any improvements over regular Apache Maven, but it can be useful to compare
   speed of other modes

The default value for this option is `--mode=native`. A throughout error message
with instructions how to continue is emitted when some necessary plugin isn't
_"baked in"_: A database of know flavors is searched and the most suitable one
is suggested. Suggestion to opt-in into `--mode=mixed` is provided as well.

## Opt-in

The whole _Native Maven_ system is designed with compatibility in mind. It is
restricted, compatible with Apache Maven. It offers the users ways to **opt-in**
into better behavior via combination of `--flavor` and `--mode` options.
Usage of these options is also _future compatible_ with new versions of _Native
Maven_. Once a project compiles, it will compile in future versions as well.
